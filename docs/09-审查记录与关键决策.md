# 09 · 审查记录与关键决策

## 9.1 首次审查（12 项，已纳入设计）
| # | 问题 | 修正 |
|---|---|---|
| 1 | 定时任务内嵌进程 → 多实例重复执行 | Celery Beat 单点 + 分布式锁 |
| 2 | 长任务同步阻塞 | 异步任务队列 |
| 3 | 无幂等 → 重复投递 | 唯一键 + Idempotency-Key |
| 4 | 状态无状态机 → 并发竞态 | 状态机 + 乐观锁 |
| 5 | 单点故障 | 无状态多实例 + 主从 + 哨兵 |
| 6 | 限流不跨实例 | Redis 分布式限流 |
| 7 | 可观测性为零 | 指标/日志/告警/链路 |
| 8 | 浏览器实例管理缺失 | 浏览器 worker 池 |
| 9 | 报表与事务库耦合 | 只读从库 + 预聚合 |
| 10 | 安全缺失 | 凭证加密 + JWT |
| 11 | LLM 单点依赖 | 熔断 + 降级规则 |
| 12 | 无备份 | 全量 + binlog 增量 |

## 9.3 关键决策记录
| 决策 | 理由 |
|---|---|
| 半自动投递 | 合规 + 降封号风险 |
| Plan C 混合采集（按平台自适应） | API 快 + 浏览器稳 |
| FAISS/pgvector 而非重型向量库 | 单机规模足够，避免运维负担 |
| Python FastAPI 而非 SpringBoot | 自动化/AI 生态更优，贴合学习方向 |
| 无状态 + 异步 + 幂等 | 高可用与可扩展的根基 |
| bge-m3 本地 embedding | 中文好、本地可跑、无外部依赖 |

## 9.4 三次审查（架构检查报告，待整改）
| # | 问题 | 检查结论 |
|---|---|---|
| R1 | 合规边界与 API 逆向/反检测存在冲突 | 需要建立平台能力白名单和禁止动作清单 |
| R2 | “无单点”目标与 Celery Beat 单点调度矛盾 | MVP 改为单机可恢复，生产再补 leader election |
| R3 | 异步任务不能天然保证 exactly-once | 按 at-least-once 设计，靠业务幂等和状态机兜底 |
| R4 | Redis 职责过多，故障域过大 | 生产拆分 broker、cache/session、lock/rate-limit |
| R5 | 投递状态机不足 | 补充 UNKNOWN、CANCELLED、DUPLICATE、HUMAN_TIMEOUT 等状态 |
| R6 | 向量检索生命周期缺失 | 补 embedding 版本、FAISS manifest、索引重建与回滚 |
| R7 | 自然语言偏好和 AI 自学习未闭环 | 增加 user_preference、user_job_feedback、behavior_embedding |
| R8 | 匹配公式缺少校准 | 硬过滤先淘汰，向量召回，LLM 做解释和精排 |

详细内容见 [10-架构检查报告.md](10-架构检查报告.md)。
