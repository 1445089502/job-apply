# 03 · 筛选匹配层（检索增强）

## 3.1 三层流水线
```
① 硬过滤（SQL/规则）     ② 向量召回（FAISS）        ③ LLM 精排
地点/薪资/语言/经验       简历embedding vs 岗位embedding   对 top-N 打分+理由
  结构化淘汰                  语义 top-50                 输出 JSON + 综合分
```

## 3.2 综合分公式
```
final = w1*硬过滤分 + w2*向量相似度 + w3*LLM分
        (0.3 / 0.3 / 0.4)
```

### ① 硬过滤（规则引擎）
- 结构化比较：城市、薪资区间、语言要求、学历、经验年限
- 示例：JD 含"日语N2" → 简历技能含"N1" → 判定满足且超标准

### ② 向量召回（FAISS）
- 简历文本 → `bge-m3` embedding
- 岗位 embedding 库 → 余弦相似度 → top-50
- 语义层面"像不像"，扩大召回

### ③ LLM 精排
```
Prompt 要求输出 JSON:
{"skill_match":0.8,"salary_match":1.0,"language_match":1.0,
 "overall":0.85,"reasons":["技能高度匹配","日语N1满足要求"]}
```
- 对 top-50 打分排序，并给出可解释理由
- 技能对比：JD 技能集 ∩ 简历技能集（Jaccard）
- 薪资对比：JD 区间 ∩ 期望区间 → 重叠度

## 3.3 降级策略
- LLM 不可用（超时/本地挂了）→ 降级为 `w1+w2`（规则 + 向量）
- 降级不阻塞投递链路（AI 匹配失败，仍可投递）

## 3.4 向量库选型
| 方案 | 特点 | 适合 |
|---|---|---|
| FAISS | 内存索引，简单 | ✅ 首选（单机够用） |
| pgvector | PG 扩展，SQL 混合查询 | 用 PG 时 |
| Chroma | 嵌入式，配 LangChain | 图省事 |
| Milvus/Qdrant | 分布式 | 岗位 >10 万才上 |
