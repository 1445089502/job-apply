# 01 · 总体架构

## 1.1 设计原则
1. **半自动、合规**：投递前人工确认，控制频率，遵守平台条款与 PIPL。
2. **异步解耦**：所有长任务（采集/投递/匹配）走异步队列，不阻塞 API。
3. **幂等 + 状态机**：重试/并发不产生副作用。
4. **高可用内建**：无单点、可降级、可观测、可水平扩展。
5. **检索增强**：SQL 硬过滤 → 向量召回 → LLM 精排。

## 1.3 技术选型
| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python FastAPI | 异步、爬虫/自动化生态最好 |
| 前端 | Vue3 + ECharts + WebSocket | 熟悉、报表友好 |
| 数据库 | MySQL（主从）+ Redis | 成熟、读写分离 |
| 向量检索 | FAISS / pgvector | 单机规模够用，避免重型向量库 |
| 自动化 | Playwright | 最成熟浏览器自动化 |
| 异步调度 | Celery + Beat + Redis/RabbitMQ | 分布式任务 + 单点调度 |
| 采集 | 混合（API 优先 + 浏览器兜底） | 见 02 |
| AI | Ollama + LangChain + bge-m3 | 本地可跑、中文好 |
| 文件 | MinIO（对象存储） | 简历版本化 |
| 部署 | Docker Compose → K8s | 单机起步可扩展 |

## 1.4 分层职责
| 层 | 职责 | 关键技术 |
|---|---|---|
| 接入层 | 路由、鉴权、限流、幂等入口 | Nginx、FastAPI、Redis |
| 业务层 | 编排、校验、状态流转（不做长任务） | FastAPI、Pydantic |
| 异步层 | 长任务执行、重试、降级 | Celery、RabbitMQ/Redis |
| 数据层 | 持久化、缓存、向量、文件 | MySQL、Redis、FAISS、MinIO |
| 可观测 | 指标、日志、告警 | Prometheus、Grafana、ELK |
