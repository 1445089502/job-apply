## 一、项目总览

### 1.1 定位
AI 辅助·半自动求职推荐与投递记录系统。核心价值：理解用户想要什么，稳定推荐值得投的岗位；自动采集/投递为受控外围能力。

### 1.2 技术栈
| 层 | 技术 |
|---|---|
| 后端 | Python FastAPI + SQLAlchemy + SQLite（可切 MySQL）|
| 向量 | numpy 余弦相似度（可换 FAISS）|
| embedding | 可插拔：Stub（离线）/ sentence-transformers（真实）|
| 前端 | 静态 SPA（HTML+JS+ECharts），FastAPI 托管 |
| 异步 | Celery（增强分支骨架）|
| 采集 | scraper 模块：真实数据集 + 智联 API（需 cookies）+ Playwright 待做 |
| 迁移 | Alembic |

## 三、架构与数据流

```
岗位数据(JSON/CSV/爬虫)
  → ingestion: 清洗/去重/入库 + embedding → vector_index
用户简历+偏好+行为反馈
  → matching: 硬过滤 → 向量召回 → 推荐+理由
用户操作(收藏/投递/不感兴趣)
  → feedback: 更新行为向量 → 影响下次排序
投递确认 → applications 记录 → statistics 报表
```

**关键依赖**：
- `runtime.py` 持有全局 `embedder` + `index`（启动时从库重建）
- `services` 依赖注入 `db session` / `embedder` / `index`，便于测试替换
- `main.py` lifespan 启动时 `init_db()` + `rebuild_index()`

## 五、检修指南（常见问题排查）

| 现象 | 可能原因 | 排查/修复 |
|---|---|---|
| `start.bat` 报"不是内部或外部命令" | bat 含中文→GBK 解析错乱 | 保持 bat 纯 ASCII（已修复）|
| 启动报 `No module named 'app'` | 运行目录不对 | 在 `backend/` 下运行 uvicorn |
| DB 数据"消失" | 启动目录不同 → 多个 SQLite | 配置已锚定项目根 `data/job_apply.db` |
| 端口 8000 被占用 | 上次服务未停 | `stop.bat` 或 `netstat -ano\|findstr 8000` 后 `taskkill /F /PID` |
| pip 装依赖报 GBK 解码错误 | Windows 编码 | `set PYTHONUTF8=1` 后再装 |
| 导入接口 422 | body 应为 `{"jobs":[...]}` 非裸数组 | 检查请求体结构 |
| curl 中文请求失败 | 控制台 GBK 破坏内联 JSON | 用 `--data-binary @file` 传 UTF-8 文件 |
| 推荐为空 | 无岗位 / 硬过滤过严 / embedding 弱 | 检查 `GET /api/jobs`、放宽 prefs |
| 推荐不精准 | 用的是 **StubEmbedder**（哈希）| 装真实 embedding 模型 |
| 智联实时抓取返回 0 | WAF 风控，未登录 | 用登录 cookies 或浏览器方式 |
| pytest 内存库不同 | 各测试共用全局 engine | `conftest.py` 用 `init_db(":memory:")` |

**调试技巧**
- 服务日志：uvicorn 输出到终端；`--reload` 改代码自动重启
- 加日志：在 service 用 `print()`（开发）或后续接 logging
- 查 SQLite：`sqlite3 data/job_apply.db "SELECT COUNT(*) FROM job;"`
- 单测调试：`pytest backend/tests/test_matching.py::test_xxx -v`

## 六、学习要点（作为学习材料）

### 6.1 核心设计模式
1. **分层**：Controller→Service→Repository（本项目为 Controller→Service→Model 直接查询）
2. **依赖注入**：FastAPI `Depends(get_db)`、测试替换 embedder/index
3. **可插拔策略**：`Embedder` 抽象（Stub 离线验证 / 真实模型）
4. **状态机**：`apply/state_machine.py` 枚举合法流转，防非法状态
5. **适配器 + 注册表**：`collectors/` 多平台统一接口
6. **幂等**：`(platform,job_id)` 唯一键，防重复导入
7. **索引与检索**：`vector_index` 把"召回"与"精排"分开

### 6.2 技术栈知识点
- FastAPI：路由、依赖、lifespan、静态托管、TestClient
- SQLAlchemy 2.0：DeclarativeBase、relationship、session
- pytest：fixtures、内存 SQLite
- numpy：向量归一化、余弦相似度
- Alembic：autogenerate 迁移
- pydantic-settings：环境变量配置

## 七、重构建议（结合 doc/10 审查 R1-R8）

### P0（上线前必做）
- **合规边界**：明确每个平台"允许/禁止/人工确认"动作清单（R1）
- **数据/凭据安全**：Cookie、简历加密；删除策略（R1/A-10）

### P1（核心链路完善）
- **真实 embedding**：装 `sentence-transformers` + `bge-small-zh`，替换 Stub（R8）
- **评分校准**：硬过滤先淘汰 → 向量召回 → LLM 精排；权重由反馈校准（R8/A-09）
- **向量生命周期**：embedding 版本、FAISS manifest、重建/回滚（R6/A-07）
- **完整状态机接入投递**：把 `apply/state_machine` 用起来（R5）
- **幂等请求表 / 任务执行表**：支撑 at-least-once（R3/A-06）
- **Celery 完整接入**：RabbitMQ、任务状态、trace_id（R2/R4）

### P2（工程质量）
- **前端工程化**：Vue3 + Vite 替换静态 SPA
- **测试补全**：状态机/幂等/导入边界；覆盖率 ≥70%
- **可观测**：SLO、指标、告警规则
- **MySQL 迁移**：Alembic 完整迁移 + 读写分离
- **偏好时间衰减**：近期行为权重更高（R7）
- **爬虫浏览器实现**：Playwright 单实例抓取（受控）

### 重构优先级建议
```
先做：真实 embedding（提升可用性）
再做：评分校准 + 向量生命周期
后做：Celery/HA/前端工程化/安全加固
```
