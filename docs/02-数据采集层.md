# 02 · 数据采集层（Plan C 混合）

> 本层是项目**最难点**，核心是"按平台自适应"的混合采集：API 优先 + 浏览器兜底 + 熔断路由。

## 2.1 采集策略（按平台自适应）
| 平台 | 主策略 | 兜底 |
|---|---|---|
| 智联 / 前程无忧 | API 优先（快） | 浏览器自动化 |
| BOSS直聘 | 浏览器优先（反爬最强） | API（若走通） |
| 猎聘 | 浏览器优先 | API |

> 理由：BOSS 接口有签名校验 + 动态 token，逆向成本高且易变；智联/前程无忧接口较开放。

## 2.2 混合适配器（Strategy + 熔断路由）
```
ChannelAdapter(接口): fetch_jobs / apply / get_status

BOSSAdapter:
  ├ api_fetcher      (requests + 签名复现 + token)
  ├ browser_fetcher  (Playwright + 登录态 + 反检测)
  └ router/breaker   先试主策略 → 失败熔断 → 切兜底 → 定时探活恢复
```

路由伪代码：
```python
def fetch_jobs(self, keyword, page):
    if self.breaker.allows("primary"):          # 熔断器放行
        try:
            jobs = self.primary_fetcher.fetch(keyword, page)
            if self._looks_valid(jobs):         # 结构/字段校验
                self.breaker.record_success()
                return jobs
        except (Blocked, SignatureError, RateLimited, SchemaChanged, Captcha):
            self.breaker.record_failure()
    return self.fallback_fetcher.fetch(keyword, page)   # 降级
```

## 2.3 浏览器自动化（Playwright）
- **登录态持久化**：cookie/storage_state 存 Redis（加密）
- **反检测**：真实 UA、关闭 `navigator.webdriver`、随机延时、行为模拟（滚动/悬停）
- **验证码/滑块**：抛 `NEEDS_HUMAN` → 前端人工介入回调
- **浏览器实例池**：复用、并发上限、防内存泄漏、容器沙箱配置

采集流程：
```
① 恢复登录态 → ② 构造搜索URL → ③ 滚动/翻页抓列表
④ 进详情抓 JD 全文/公司/技能 → ⑤ 标准化 Job → 入库
```

## 2.4 API 逆向（Plan B）
```
① 抓包(DevTools/Charles) 定位 XHR/JSON 接口
② 提取参数 + cookie + token
③ 复现签名(如 BOSS __zp_stoken__)，可用 PyExecJS/node 执行平台 JS
④ 请求 → JSON → 标准化
```
- token 失效自动续/重登
- **注意**：签名逆向维护成本高 → 仅对接口开放的平台作为主策略

## 2.5 限速与反风控
- Redis 令牌桶，**按账号+平台**限速
- 每日投递/浏览上限
- 失败重试：指数退避 + 抖动
