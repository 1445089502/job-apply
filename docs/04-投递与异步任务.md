# 04 · 投递服务与异步任务

## 4.1 投递状态机
```
CREATED → QUEUED → APPLYING → SUCCESS
                          ↘ NEEDS_HUMAN（验证码/异常）→ 人工处理后 → APPLYING
                          ↘ FAILED（可重试）
```
- 数据库 `version` 乐观锁，防并发覆盖
- 状态变更写 `apply_event` 流水（审计）

## 4.2 幂等设计
- **唯一键**：`(platform, job_id, user)`
- **请求幂等**：`Idempotency-Key` 头，重复提交直接返回原结果
- 效果：网络重试 / 任务重放零副作用

## 4.3 投递中断补偿
- 事务日志可回放
- 半完成（已填未提交）→ 标记待人工 → 人工介入队列
- 失败重试：指数退避 + 抖动，有限次

## 4.4 异步任务架构
```
业务层提交任务 → Celery Broker(Redis/RabbitMQ) → Worker 执行 → 回调更新状态
```
| Worker | 职责 |
|---|---|
| 采集 worker | Playwright 浏览器池采集岗位 |
| 投递 worker | 幂等/限速/反风控/重试 |
| 匹配 worker | embedding + FAISS 召回 + LLM 精排 |

## 4.5 调度防重（HA 关键）
- **Celery Beat 单点调度**（避免多实例重复触发）
- 每个任务带**唯一 task_id**
- Redis 分布式锁（`SETNX`）保证同一任务全局只执行一次

## 4.6 API 与任务的交互
- API 提交任务 → 立即返回 `task_id`
- 前端轮询 / WebSocket 拿进度
- 任务支持：进度查询、取消、人工介入回调
