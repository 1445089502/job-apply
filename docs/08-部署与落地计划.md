# 08 · 部署与落地计划

## 8.1 部署拓扑

### 单机（开发 / 个人使用）
```
docker-compose:
  nginx        → 8080
  api          → FastAPI 实例
  worker       → Celery worker（采集/投递/匹配）
  beat         → Celery Beat（调度）
  mysql        → 主库
  redis        → 缓存/队列/锁
  minio        → 简历对象存储
  grafana      → 看板（可选）
```

### 扩展路径
```
单机 → 应用多实例 + LB → worker 扩容 → MySQL 主从 → Redis 哨兵 → K8s
```

## 8.2 CI/CD
- GitHub Actions：lint + 单测 + 构建镜像 + 部署
- 多环境：dev / staging / prod（环境变量隔离）
- DB 迁移：Alembic/Flyway，版本管理，升级不丢数据

## 8.3 分阶段落地计划

| 阶段 | 内容 | 周期 |
|---|---|---|
| **P1 MVP** | 1 个平台适配器 + 采集入库 + 硬过滤 + 投递漏斗报表 + Vue 看板 | 2-3 周 |
| **P2** | 混合适配器（API+浏览器+熔断）、向量召回、投递队列、人工介入 | +2 周 |
| **P3** | LLM 精排、自荐信生成、RAG 偏好学习、定时报告、可观测 | +2 周 |
| **P4** | 多平台、HA 加固、备份、CI/CD | 按需 |

### P1 MVP 具体范围
- 后端：FastAPI + MySQL/Redis，岗位采集（先 1 平台）入库
- 匹配：先只做硬过滤（SQL）
- 投递：手动触发 + 状态记录（先不做浏览器自动投递）
- 报表：投递漏斗 + ECharts
- 前端：Vue3 看板 + 筛选页

## 8.4 风险与对策

| 风险 | 对策 |
|---|---|
| 平台封号 | 限速 + 半自动 + 模拟真人 + 多账号隔离 |
| API 改版/签名变化 | 熔断自动切浏览器；结构化校验告警 |
| 验证码 | 人工介入回调 |
| LLM 成本/超时 | token 配额 + 缓存 + 降级规则 |
| Prompt 注入（恶意 JD） | JD 清洗 + LLM 输出校验 + 提示词隔离 |
| 合规 | 个人使用、数据最小化、可删除 |
