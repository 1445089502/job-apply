# 13 · 自动化增强版说明（分支 feat/automation-ha）

> 分支：`feat/automation-ha`
> 与 `main`（合规 MVP）并行：**main 保持"推荐匹配 + 人工投递记录"**；本分支构建**全自动投递 / 多平台爬取 / HA** 增强能力。

## 一、定位与边界

| 维度 | main（MVP） | feat/automation-ha（本分支） |
|---|---|---|
| 采集 | 低风险/人工导入 | **多平台 Plan C 混合采集** |
| 投递 | 人工确认后投递 | **全自动投递（受控）** |
| 高可用 | 单机可恢复 | **无单点 + 异步 + 可观测** |
| 合规 | 严格半自动 | 受控自动（频率克制 + 白名单）|

## 二、本分支要做的三块能力

### 1. 多平台爬取（采集适配器）
- 抽象 `ChannelAdapter` 接口：`fetch_jobs / apply / get_status`
- 适配器注册表：`BOSSAdapter / ZhilianAdapter / LiepinAdapter / 51JobAdapter`
- **Plan C 混合**：每平台一个适配器，API 优先 + 浏览器(Playwright)兜底 + 熔断路由
- 统一 `Job` 模型 + 清洗去重 + 数据校验
- 见 `docs/02-数据采集层.md`

### 2. 全自动投递（扩展状态机 + 幂等）
- 扩展状态：`UNKNOWN / CANCELLED / DUPLICATE / HUMAN_TIMEOUT / SUBMITTED_UNCONFIRMED`（doc 10 A-05）
- 自动提交：填表 → 上传简历 → 提交 → 确认结果
- 幂等：`(platform, job_id, user)` 唯一键 + `Idempotency-Key`
- 中断补偿：事务日志 + 人工介入队列
- 见 `docs/04-投递与异步任务.md`

### 3. 高可用（异步 + 无单点 + 可观测）
- 异步任务：Celery + RabbitMQ（替代内嵌调度）
- Redis 职责拆分：broker / cache-session / lock-rate-limit
- 多实例无状态 API + LB
- MySQL 主从、MinIO、可观测（Prometheus/Grafana）
- 见 `docs/06-高可用与可靠性.md`、`docs/07-可观测与安全.md`

## 三、对照三次审查（doc 10 R1-R8）整改
| 项 | 本分支落实 |
|---|---|
| R1 合规边界 | 建立平台能力白名单 + 禁止动作清单 |
| R2 调度单点 | 生产引入 leader election / 外部调度器 |
| R3 exactly-once | at-least-once + 业务幂等兜底 |
| R4 Redis 拆分 | broker / cache / lock 分 Redis 或独立 |
| R5 状态机 | 扩展 UNKNOWN/CANCELLED/DUPLICATE/HUMAN_TIMEOUT 等 |
| R6 向量生命周期 | embedding 版本 + FAISS manifest + 重建/回滚 |
| R7 偏好学习 | user_preference / user_job_feedback / behavior_embedding |
| R8 匹配校准 | 硬过滤先淘汰，向量召回，LLM 解释+精排 |

## 四、目录新增（本分支）
```
backend/app/
  collectors/        # 采集适配器（ChannelAdapter + 注册表 + 各平台）
  apply/             # 全自动投递（状态机 + 幂等 + 补偿）
  workers/           # Celery 任务
  services/          # 业务逻辑增强
docker-compose.yml   # HA 环境（MySQL/Redis/RabbitMQ/MinIO）
```

## 五、风险提示
- 全自动投递/爬取存在**封号与合规风险**，须：频率克制、平台白名单、个人使用、可随时降级回 main。
- 本分支代码仅供学习与技术验证，上线前必须完成合规评估。
